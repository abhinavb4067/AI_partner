=== BUG FOUND (NOT YET FIXED) ===
File: mobile_app/lib/screens/chat/chat_screen.dart, function _loadHistory()
Problem: `_error` is set when the history fetch fails, but is never cleared back to
null on a subsequent successful/retried load. There is also no retry button anywhere
in the UI. Net effect: if the very first history load fails (e.g. flaky network on
cold start), the chat screen gets stuck showing the error message permanently with no
way to recover except leaving and re-entering the screen. This is the closest match
in the code to a "chat screen goes blank / stuck" symptom.
Fix needed:
  1. Reset `_error = null` at the top of `_loadHistory()` before the try block.
  2. Add a retry button/action in the error-state UI (around line 228-229) that calls
     `_loadHistory()` again.

--- 1. SECURITY FIXES (all deployed) ---
Critical:
  - chat.py: POST /api/chat/ and GET /api/chat/history/{char_id} now require JWT
    auth (Depends(get_current_user)) — previously anyone could chat as/drain
    credits of/trigger paid image-gen for ANY user by just knowing their email,
    since user_id came from the request body, not the token.
  - payment_service.py: removed the "if 'DUMMY' in key: auto-approve" bypass.
    Replaced with explicit PAYMENT_MOCK_MODE setting (default False) + fails
    CLOSED (rejects) when gateway keys are missing/unconfigured.
High:
  - Added slowapi rate limiting: login/register/OTP/reset-password (5/min),
    chat (20/min), chat history (60/min), TTS/transcribe (10/min).
  - /api/payment/verify now has an idempotency guard (can't be credited twice).
  - config.py refuses to boot if CORS_ORIGINS contains "*" (paired with
    allow_credentials=True that's a token-theft vector).
Medium/low:
  - Google-only accounts (empty hashed_password) can no longer be silently
    hijacked by whoever calls /login first with any password.
  - main.py refuses to boot in production with the default admin password.
  - Media (AI-companion chat photos at /media/<char>/<user>/<file>) is now
    auth-gated + ownership-checked via new app/api/routes/media.py — this
    ALSO required an nginx fix (nginx_backend.conf) since nginx was serving
    /media/ directly via `alias`, bypassing FastAPI entirely; added a regex
    location for the 3-segment path shape that proxies to the backend instead.
  - WebSocket auth token moved off the URL path onto the Sec-WebSocket-Protocol
    subprotocol (ws_chat.py) so it stops appearing in proxy logs/browser
    history. Old /{token} route kept one release as a fallback.
  - requirements.txt fully pinned to versions verified via `pip freeze` on the
    actual production venv (not just latest-locally-installed).
  - ADMIN PASSWORD WAS CHANGED on the server — new password is in
    backend/.env on the server (ADMIN_PASSWORD=...) and was shown once to the

--- 3. NSFW IMAGE GENERATION: root cause found, provider research done, NOT YET FIXED ---
  With logs now working, caught the real failure live: fal.ai's fast-sdxl
  (yesterday's fix) returns HTTP 422 content_policy_violation on NSFW
  prompts. Checked fal.ai's own docs (fal.ai/docs/errors): NSFW is
  EXPLICITLY listed as a policy-violation trigger, marked non-retryable, no
  account setting/parameter/alternate endpoint can disable it. This is a
  hard platform-wide ban, not a bug -- fal.ai categorically cannot be used
  for NSFW generation, full stop.

  User does NOT want fal.ai removed (already paid ~Rs1000 for a
  subscription) -- keep it for SFW image generation only, find a separate
  provider for NSFW.

  Research done (checked each provider's ACTUAL policy docs, not just
  marketing, after confirming fal.ai's marketing was misleading):
    - Novita AI: looked promising (cheap $0.0015/img, true pay-as-you-go,
      "optional NSFW detection" language suggested no blanket ban) BUT their
      Acceptable Use Policy Section 5(7) explicitly states content that "is
      sexually explicit" is prohibited, no carve-out for consenting adults.
      Confirmed dead end via https://novita.ai/legal/acceptable-use-policy
      -- do NOT use for NSFW.
    - ModelsLab (formerly stablediffusionapi.com) -- STRONGEST CANDIDATE:
      their own product docs explicitly document a model_id="nsfw" and a
      "safety_checker": "no" request parameter -- this is a documented,
      marketed feature, not an accidental loophole. Their ToS doesn't ban
      adult content (unlike Novita's explicit ban). Endpoint:
      https://modelslab.com/api/v7/images/text-to-image (or v4/dreambooth
      for the "nsfw" model specifically), key passed in JSON body not header.
      Pricing: NO free trial, Basic plan $21/mo (~Rs1750) for 3,250 calls/mo
      (~Rs0.54/image AT FULL 3250-image usage; effectively a flat ~Rs1750/mo
      cost at current low volume since unused calls likely don't roll over).
      Has a genuine 24-hour full-refund window on NEW subscriptions only
      (not renewals) -- this is the safety net: subscribe, test immediately,
      cancel within 24h for full refund if it doesn't actually work.
      One unrelated Trustpilot complaint found about general output
      relevance/quality ("asked for a house, got a horse") -- not NSFW
      specific, just a quality flag to keep in mind.

  DECISION NOT YET MADE: user was weighing whether the effective ~Rs1750/mo

  right now vs waiting. Nothing purchased, nothing implemented yet.
